\label{sec:higher-order}

In this section, we present a functional programming language that defines exactly the polyregular functions. This language grows out of the term based approach from \cref{sec:regular-list-functions}, but thanks to the extra expressive power of polyregular functions, the language can be equipped with programming constructions that make it quite usable.

\subsection{Polyregular terms}
\label{sec:polyregular-terms}
Before presenting the full programming language, we begin with a minimal adjustment to the term based approach from \cref{sec:regular-list-functions} which enables us to cover polyregular functions. This adjustment  is to add one new atomic function, which can be  seen as a kind of loop that iterates over all splits of an input list.

\begin{definition}[Polyregular terms]\label{def:polyregular-terms}
    A \emph{polyregular term} is a term built using the atomic functions and combinators from \cref{def:regular-terms}, extended by one additional atomic function:
    \begin{align*}
    A^*  & \xrightarrow{\splitterm} (A^* \times A^*)^* \\
    [a_1,\ldots,a_n] & \mapsto \myunderbrace{[([a_1,\ldots,a_{n}],[]),  ([a_1,\ldots,a_{n-1}],[a_n]), \ldots , ([],[a_1,\ldots,a_{n}])]}{the input list is split into (prefix, suffix) pairs in all possible ways, \\ with the prefix getting shorter as we move to the right}.
\end{align*}
\end{definition}


\begin{myexample}[Split and marked square] \label{ex:split-and-marked-square} The split function is essentially the type-to-type version of the string-to-string function for marked squaring that is the basis of polyregular function. Since strings over a finite alphabet are a special case of types, we can try to recover marked squaring. This is done as follows. We begin with the composition
    \begin{align*}
A^* 
\xrightarrow \splitterm 
(A^* \times A^*)^* 
\xrightarrow {(\leftterm^* \times \rightterm^*)^*}
((A+A)^* \times (A+A)^*)^*
\xrightarrow {\binconcterm^*}.
(A+A)^{**}
\end{align*}
Then we reverse the list, remove the first item, and apply  $\concatterm$ to flatten it. The converse simulation also holds: if we think of the split function as a string-to-string function, under string representation of types, then it is polyregular.  In fact, it can be obtained by applying marked squaring to the (string representation of the) input list, followed by a rational function that erases some of the extraneous annotation. 
\end{myexample}


In the exercises we show  $\blockterm$ and $\reverseterm$  become  redundant in the presence of $\splitterm$, and the group prefix multiplication function can be simplified (although not altogether eliminated) so that its type is $G^* \to G$ and not $G^* \to G^*$. We now show that the polyregular terms define exactly the polyregular functions. The functions in question are type-to-type functions, with the notion of polyregularity being defined using string representations as in \cref{def:polyregular-functions}. 





\begin{theorem}  \label{thm:polyregular-terms} A type-to-type function is polyregular under string representation  if and only if it can be defined by a polyregular term.
\end{theorem}
\begin{proof}
    Both implications are easy to show. 
    For the right-to-left implication: the combinators are easily seen to preserve polyregularity, the old atomic functions are regular and thus also polyregular, and the polyregularity of split was argued in Example \ref{ex:split-and-marked-square}. For the left-to-right implication, we use the definition of polyregular functions in terms of compositions of primes from \cref{def:polyregular-functions}; in this case it is enough to show that marked squaring can be expressed using $\splitterm$, which was also argued in Example \ref{ex:split-and-marked-square}.
\end{proof}











\subsection{Higher-order polyregular terms}
\label{sec:syntax-and-semantics-of-higher-order-terms}

The system from \cref{thm:polyregular-terms} is only a minor variation on the system of combinators from \cref{sec:regular-list-functions}, and is essentially a warm-up for the real contribution of this section, which is a kind of functional programming language. 

Functional programming languages are based on the $\lambda$-calculus, where the  basic computational mechanism  is substitution:  a variable is replaced by its argument. Since a variable can appear multiple times, such substitution can lead to super-linear output size. For example, the squaring operation from \cref{exer:squaring-continuous}, which had quadratic output size, can be implemented by the following  code, which replaces each list element by the list itself:
\begin{align*}
\lambda x. \concatterm\ ( \mapterm\ (\lambda y. x)\  x).
\end{align*}
Because of the super-linear output size, we avoided substitution in the previous parts of this book, which were about functions with linear output size.
Now, in the presence of polynomial size, we can  embrace substitution. This is what we do in this section: we define a functional programming language which defines exactly the polyregular functions. 

Like essentially all functional programming languages, our language will have higher-order functions, so that  functions can input other functions, or even more complicated objects. For example, a legitimate type in our language will be 
\begin{align*}
\myunderbrace{(\onetype^* \to (\onetype + \onetype))}{inputs are functions from natural numbers to Booleans} \to \onetype + \onetype.
\end{align*}
 The functions can be themselves nested with the other type constructors, e.g.~we have a type for lists of functions as in the above type.  The corresponding set of types is defined below.





\begin{definition}
    [Higher-order types] \label{def:higher-order-types}  The \emph{higher-order types} are defined by extending the grammar of types in \cref{def:types} with an arrow constructor $A \to B$. 
\end{definition}

As was the case in \cref{sec:regular-list-functions}, each type represents a set. For the arrow constructor $A \to B$, the represented set consists of total functions from the set represented by $A$ to the set represented by $B$. (Our programs will be always-terminating, which is why we use total functions.) By abuse of notation, we use the same symbol for a type and the set that it represents.


Our programming language is the extension of the polyregular terms with the mechanics of the  $\lambda$-calculus, namely variables, application and abstraction. We use a variant of Church style typing, where each variable comes hard-wired with a type, and therefore each term has a unique type, which can be inferred by a bottom-up analysis. For the rest of this section, we assume that there is some set of variables, each one with an associated higher-order type, such that each higher-order type has infinitely many variables. The syntax of the programming language is defined below.
\begin{definition}[Higher-order polyregular terms]
    \label{def:higher-order-terms}
    The syntax of \emph{higher-order  polyregular terms} is  defined by induction as follows:
        \begin{description}
            \item[atomic functions and combinators:] we keep all atomic functions and combinatosrs of the polyregular terms, which are now also allowed for higher-order types; 
             \item[variable:]        each variable is a higher-order polyregular term of corresponding type;
            \item [application] if $f : A \to B$ and $a : A$ are higher-order polyregular, then so is $f(a) : B$;
            \item [abstraction] if $b : B$ is a higher-order polyregular term and $x : A$ is a variable, then $\lambda x. b : A \to B$ is a  higher-order polyregular term.
        \end{description}
\end{definition}

The semantics of the programming language is defined in the expected way. For a term $a : A$ that has free variables  $x_1 : A_1, \ldots, x_n : A_n$,  its semantics $\sem a$ is the  function  of type 
\begin{align*}
 {A_1} \times \cdots \times  {A_n} \to A
\end{align*}
which is defined by induction on the structure of the term in the expected way.  Later in this section, we will show that the higher-order polyregular terms define exactly the polyregular functions in those cases where they can be compared: the inputs and outputs are arrow-free types.




\paragraph*{An alternative syntax.} The definition of higher-order polyregular terms from \cref{def:higher-order-terms} was phrased as an extension of the polyregular terms. However, if we were to build the programming language from scratch, without some legacy language that is built on atomic functions and combinators, we would be more likely to design a different syntax, such as the one in the following lemma.  In the lemma below, $\multterm$ is the function that multiplies elements in a group, and $\mapterm$ as well as $\mathtt{either}$ are defined as in Haskell.


\begin{lemma}\label{lem:fewer-atomic}
    The expressive power of the higher-order polyregular terms is  not changed if we do the following three modifications (all need to be done together): 
    \begin{itemize}
        \item remove the combinators;
        \item add term constructors for the arrow-free type constructors: 
        \begin{align*}
        1 : \onetype \quad (a,b) : A \times B \quad \leftterm a, \rightterm b : A+B \quad [a_1,\ldots,a_n] : A^*;
        \end{align*}
        \item have the following atomic functions:
            \begin{align*}
            \fstterm : &\  A \times B  \to A \\
            \sndterm : &\  A \times B  \to B \\
            \unconsterm : &\  A^* \to \onetype + A \times A^*\\
            \concatterm : &\ A^{**} \to A^* \\
            \splitterm : &\ A^* \to (A^* \times A^*)^*  \\
            \multterm : &\  G^* \to G  \\
        \mapterm  : &\   (A \to B) \to A^* \to B^* \\
        \mathtt{either}  : &\  (A \to C) \to (B \to C) \to (A+B) \to C.
        \end{align*}
    \end{itemize}
\end{lemma}
\begin{proof} Let us prove one of the implications in the lemma, which is that the modified version is at least as expressive as the original one from \cref{def:higher-order-terms}. The other implication is left as an exercise for the reader. The combinators can be implemented using the term constructors: 
    \begin{align*}
    f_1; f_2 & =  \lambda x. f_2 (f_1 x)\\
    f_1 \times f_2 & =  \lambda x. (f_1 (\fstterm x), f_2 (\sndterm x))\\
    f_1 + f_2 & =  \lambda x. \either (\lambda y. \leftterm\ (f_1\ y))\ (\lambda z. \rightterm\ (f_2\ z))\ x \\
    f^* & = \mapterm f 
    \end{align*}
    Therefore, it remains to show that all of the atomic polyregular functions can be implemented using the modified syntax. In \cref{exer:reverse-from-split} we show that $\reverseterm$ is redundant, in \cref{exer:block-from-split} we do the same for $\blockterm$, and in \cref{exer:pref-from-mult} we show that the group prefix operation can be replaced by the $\multterm$. The other missing atomic functions are implemented as follows:
         \begin{align*}
        \idterm  &=  \lambda x.x \\
        \diagterm  & = \lambda x. (x,x) \\
        \codiagterm & = \either (\lambda x.x) (\lambda x.x) \\
        \distrterm & = \lambda x.\  \either 
        (\lambda y. \leftterm\ (\fstterm\ x, y))\  
        (\lambda y. \rightterm\ (\fstterm\ x, y))\ 
        (\sndterm\ x) \\
        \consterm  & = \either (\lambda y. [])\ 
        (\lambda y. \concatterm [ [\fstterm y], \sndterm y] ) .
    \end{align*}
\end{proof}


\subsection{Expressive completeness}
\label{sec:expressive-completeness}
Higher-order polyregular terms can define functions of higher-order types for which we have no notion of polyregularity. However, we now show that for functions between arrow-free types, the higher-order polyregular terms define exactly the polyregular functions. In other words, the higher-order features do not create any new expressivity, at least as long as we care about functions between arrow-free types. 




\begin{theorem}\label{thm:higher-order-terms}
    Consider a function 
    \begin{align*}
    A \xrightarrow f B
    \end{align*}
    where the types $A$ and $B$ are arrow-free, i.e.~constructed without using the arrow type constructor. Then $f$ is polyregular if and only if it can be defined by a higher-order polyregular term which is closed (i.e.~has no free variables).
\end{theorem}

One implication of the theorem is clear: the higher-order programming language was defined as an extension of polyregular terms, and therefore it is at least as expressive by definition. The difficult part is the converse implication: the higher-order features do not increase the expressiveness. To prove the difficult implication, we will use an unusual semantics for higher-order polyregular terms, which is based on a technique from the $\lambda$-calculus that is called \emph{logical relations}. 

\newcommand{\semparam}[2]{\sem{#1}_{#2}}
For the rest of this section, we use the name \emph{term} for higher-order polyregular terms. When defining the semantics of our programming language, we assigned to each term  $a : A$ a denotation, which was a function 
\begin{align*}
\myunderbrace{{A_1} \times \cdots \times {A_n}}{values for the free variables} \xrightarrow {\sem a } {A}.
\end{align*}

However, in the proof of \cref{thm:higher-order-terms} we will use a more elaborate denotation, which will be parametrised by an arrow-free type $Q$. In this more elaborate approach, the denotation of a  term is not a single value, but a family of values indexed by parameter set $Q$, and the same is done for the free variables. Therefore, the denotation of a term $a$ under parameters $Q$ is a function 
\begin{align*}
(Q \to A_1)\times \cdots \times (Q \to A_n) \xrightarrow{\semparam a Q} {Q \to A}.
\end{align*}
This new parameterised denotation is  defined to be  pointwise lifting of the original one: 
\begin{align*}
\sem a_Q \myunderbrace{(\rho_1,\ldots,\rho_n)}{the values for free variables} \myoverbrace{(q)}{the parameter} = \sem{a}(\rho_1(q),\ldots,\rho_n(q)).
\end{align*}
At first sight, this  seems to be a mere obfuscation of the original semantics. However, the new definition  will enable us to find an invariant that will be used to remove the higher-order features of  higher-order polyregular terms.  This invariant is postulated in the following lemma. It is usually called logical relaitons, but  since we use both logics and relations in other ways, and we use the non-descriptive name of \emph{good functions} below.

\begin{lemma}[Fundamental Lemma] \label{lem:fundamental-lemma} For every arrow-free type $Q$ and higher-order type $A$, one can identify  a subset of the functions of type $Q \to A$, called the \emph{good functions}, such that:
\begin{enumerate}
    \item When $A$ is arrow-free, good functions  are exactly the polyregular ones.
    \item  Consider the parametrised denotation  $\sem a_Q$ of a higher-order polyregular term with $n$ free variables. If the parameterized values $\rho_1,\ldots,\rho_n$ for the free variables are good, then the same is true for $\sem a_Q (\rho_1,\ldots,\rho_n)$.
\end{enumerate}
\end{lemma}

Before proving the Fundamental Lemma, we use it prove \cref{thm:higher-order-terms}. 
\begin{proof}[Proof of \cref{thm:higher-order-terms} using the Fundamental Lemma.]  As we have explained before, we only need to show that if a function between arrow-free types is defined by a closed higher-order polyregular term, then it is polyregular.  Suppose that $f$ is a closed higher-order polyregular term, whose type is $A \to B$ for some arrow-free types $A$ and $B$. Choose a variable $x : A$, let the parameter set be $A$ itself, and  consider the parametrised denotation $\sem{f(x)}_A$ of the application term $f(x)$. We apply this denotation to the identity function on the set $A$, which is good by the first item of the Fundamental Lemma. By the second item, 
    \begin{align*}
   A \xrightarrow{\sem{f(x)}_A \idterm}B
    \end{align*}
    is good, and thus polyregular by the first item.  This function is the same as the usual denotation $\sem f$.
\end{proof}


It remains to prove the Fundamental Lemma. We begin by defining the notion of good functions of type $Q \to A$. This is done by induction on the structure of the type $A$. Although unsurprising at first glance, the fact that we are able to pull off such an induction is the whole point of the parametric approach.  Indeed, if we want to analyse a higher-order term of type $A \to B$, the argument $A$ might be constructed using other higher-order types that are possibly more complex than both $A$ and $B$, and thus there does not seem to be any obvious way to appeal to induction. As it turns out, the presence of a parameter set $Q$ will allow us to do precisely that, by putting the complexity of the argument into the parameter set, without having to consider more complex types than $A$ or $B$.

\begin{definition}
    [Good functions]\label{def:good-function}\ 
    \begin{itemize}
        \item \textbf{Unit.} The unique function of type $Q \to \onetype$ is good.
        
        \item \textbf{Types other than arrow.} Good functions with an output product type $A_1 \times A_2$ are exactly the compositions 
        \begin{align*}
        Q \xrightarrow f Q_1 \times Q_2 \xrightarrow {\rho_1 \times \rho_2} A_1 \times A_2
        \end{align*}
        for some arrow-free types $Q_1$ and $Q_2$, some polyregular $f$, and some good $\rho_1$ and $\rho_2$. Similarly we define functions with outputs that are co-products or lists, with the compositions being 
                \begin{align*}
        Q \xrightarrow f Q_1+Q_2 \xrightarrow {\rho_1 + \rho_2} A_1 + A_2 \qquad 
        Q \xrightarrow f  P^* \xrightarrow {\rho^*} A^*,
        \end{align*}
        where the new parameter types $Q_1,Q_2$ and $P$ are again required to be arrow-free.
        \item \textbf{Arrow types.} For an arrow output type, a function 
        \begin{align*}
        Q \xrightarrow \rho (A \to B)
        \end{align*}
        is  good if for every 
        \begin{itemize}
            \item arrow-free type $P$ called the \emph{new parameters};
            \item polyregular function $P \xrightarrow r Q$ called the \emph{change of parameters};
            \item good $P \xrightarrow \sigma A$,
        \end{itemize}
        the following function is good
        \begin{align*}
            p \in P \quad \mapsto \quad  \rho(r(p)) \text{ applied to } \sigma(p).
        \end{align*}
    \end{itemize}
\end{definition}

We begin with the first item of the Fundamental Lemma.
\begin{lemma}\label{lem:good-functions-are-polyregular-at-arrow-free-types}
    If $Q$ and $A$ are arrow-free, then good functions of type $Q \to A$ are exactly the polyregular ones.
\end{lemma}
\begin{proof}
    A simple induction on the structure of $A$. When $A$ is the unit type, there is nothing to do. Suppose that the output type is a list type  $A^*$, in which case the good functions are those of the form 
    \begin{align*}
    Q \xrightarrow f  P^* \xrightarrow {\rho^*} A^*.
    \end{align*}
    For the implication good-to-polyregular, we apply the induction assumption to the good function $\rho$, and use the fact that polyregular functions are closed under composition and map. For the converse implication, we put the entire polyregular function into $f$, with $P=A$ and $\rho$ being the identity function on $A$. The product and co-product cases are similar.
\end{proof}

The crux of the matter is the second item of the Fundamental Lemma, which says that semantics of higher order polyregular terms are consistent with good functions. This is proved by induction on the structure of the term.


\newcommand{\fundlemlogrel}[2]{\sem{#1}_{#2}}



\paragraph*{Variables.} The case of variables is immediate, since $\semparam x Q \rho$ is the same as $\rho$, and thus good by assumption. 

\paragraph*{Application.} Consider now the parameterised denotation of an application term
 \begin{align*}
Q \xrightarrow{\semparam{f(a)}Q  (\rho_1,\ldots,\rho_n)} B,
\end{align*} 
where $f$ is a term of type $A \to B$ and $a$ is a term of type $A$. We want to show that this denotation is a good function. The subterms $f$ and $a$ do not need to use all free variables; without loss of generality we assume that $f$ uses some prefix of the free variables and $a$ uses some suffix. By induction assumption, we know that 
\begin{align*}
\semparam f Q (\rho_1,\ldots,\rho_i) \qquad 
\semparam a Q (\rho_j,\ldots,\rho_n)
\end{align*}
are good functions. The function corresponding to $f$ has an arrow type, and thus we can use the definition of good functions at arrow types, with the parameter change being the identity and the argument being the denotation of $a$, to conclude that the following function is good: 
\begin{align*}
q \in Q \quad \mapsto \quad (\semparam f Q (\rho_1,\ldots,\rho_i)) (q) \text{ applied to argument } (\semparam a Q (\rho_j,\ldots,\rho_n)) (q).
\end{align*}
This function is exactly the parameterised denotation of $f(a)$, and thus we are done.

\paragraph*{Abstraction.} Consider now the parameterised denotation of an abstraction term 
\begin{align*}
Q \xrightarrow{\semparam{\lambda x : A.b}Q (\rho_1,\ldots,\rho_n)}{A \to B}
\end{align*}
We want to prove that this is a good function. 
By unfolding the definition of the above denotation and the definition of good functions at arrow types, we need to show that for every arrow-free type $P$, every polyregular change of parameters $r : P \to Q$ and every good function $\sigma : P \rightarrow  A$, the following function is good:
\begin{align*}
p \in P \quad \mapsto \quad \sem b (\rho_1(r(p)),\ldots,\rho_n(r(p)), \sigma(p)).
\end{align*}
This function is the same as $\semparam b P$ applied to parameterised valuations $\rho_1 \circ r, \ldots, \rho_n \circ r$ and $\sigma$. If we could show that these values are good, then we could use the induction assumption of the Fundamental Lemma for $b$ to conclude. The value $\sigma$ is good by assumption, and the values $\rho_i \circ r$ are good by the following claim, which says that good functions are closed under pre-composition with polyregular functions.
\begin{claim}\label{claim:logical-relations-closed-under-precomposition}
    Good functions are closed under pre-composition with polyregular ones.
\end{claim}
\begin{proof}
    Induction on the structure of the output type. For the unit type there is nothing to do, and for product, co-product and list types the claim follows from the definition of good functions for such types, where the composition begins with a polyregular function. The final case is the arrow type. By recalling the definition in an arrow type $A \to B$, we need to show that 
    \begin{align*}
        \forall P \xrightarrow r Q \ \forall P \xrightarrow \sigma A \qquad
            p \in P \ \mapsto \  \rho(r(p)) \text{ applied to } \sigma(p) \quad \text{is good}.
        \end{align*}
    To prove the claim, we need to show that if the above condition is true for $\rho$, then it remains true after $\rho$ has been pre-composed with a polyregular function $s$. This is indeed true, since $r$ is quantified universally, and thus it can consume the part of $\rho$ that begins with $s$. 
\end{proof}


\paragraph*{Combinators.} We now show the induction step for combinators. 
We only deal with the combinator $f^*$ for lists, with the other combinators being similar. Consider the parameterised denotation 
\begin{align*}
Q \xrightarrow{\semparam {f^*} Q (\rho_1,\ldots,\rho_n)}{A^* \to B^*},
\end{align*}
which by definition is the function 
\begin{description}
    \item [Type] $Q \to (A^* \to B^*)$;
    \item [Input 1] $q \in Q$;
    \item [Input 2] $[a_1,\ldots,a_m] \in A^*$;
    \item [Output] list where the $i$-th entry is $\sem f (\rho_1(q),\ldots,\rho_n(q))(a_i)$.
\end{description}
We want to show that this function is good. Since the output type $A^* \to B^*$ is an arrow type, the definition of good functions says that we need to show that for  every polyregular change of parameters $r : P \to Q$ and every good function $\sigma : P \to A^*$, the following is  good:
\begin{description}
    \item [Type] $P \to B^*$;
    \item [Input] $p \in P$ where   $[a_1,\ldots,a_m]$ is defined to be $\sigma(p)$;
    \item [Output] list where the $i$-th entry is $\sem f (\rho_1(r(p)),\ldots,\rho_n(r(p)))(a_i)$.
\end{description}
By definition of good functions,  $\sigma$ is a composition
\begin{align*}
P \xrightarrow h R^* \xrightarrow {\tau^*} A^* \qquad \text{for some polyregular $h$ and good $\tau$}.
\end{align*}
Therefore, we need to show that the following  is good:
\begin{description}
    \item [Type] $P \to B^*$;
    \item [Input] $p \in P$ where   $[c_1,\ldots,c_m] \in R^*$ is defined to be $h(p)$;
    \item [Output] list where the $i$-th entry is $\sem f (\rho_1(r(p)),\ldots,\rho_n(r(p)))(\tau(c_i))$.
\end{description}
This is the same as composition of the polyregular function 
\begin{align*}
p \in P  \quad \mapsto \quad [(p,c_1),\ldots,(p,c_m)]
\end{align*}
followed by the  list combinator applied to the following function
\begin{description}
    \item [Type] $P \times R \to B$;
    \item [Input] $(p,c) \in P \times R$;
    \item [Output]  $\sem f (\rho_1(r(p)),\ldots,\rho_n(r(p)))(\tau(c))$.
\end{description}
In the output above, we use parameterised values which are obtained from $\rho_1,\ldots,\rho_n$ and $\tau$ by pre-composition with polyregular functions. Therefore, the above function is good by induction assumption and \cref{claim:logical-relations-closed-under-precomposition}. This completes the proof for the list combinator. 




\paragraph*{The list constructor.}  We are now left with the atomic functions. We begin by discussing a simple case of an atomic function, which is the list constructor
\begin{align*}
\onetype + A \times A^* \xrightarrow \consterm A^*.
\end{align*}
This term has no free variables, and therefore the conclusion of the Fundamental Lemma in this case says that for every arrow-free $Q$, the constant function  of type
\begin{align*}
q \in Q \quad \mapsto \quad \consterm 
\end{align*}
is good. By unfolding the definition of good functions for  $\onetype + A \times A^* \to A^*$, this means that for every arrow-free parameter type $P$, every polyregular change of parameters $f : P \to Q$ and every good $\sigma : P \to \onetype + A \times A^*$, 
the function 
\begin{align*}
p \in P \quad \mapsto \consterm (\sigma(p))
\end{align*}
is good. (The change of parameters is not used, since our original good function ignored the parameter from $Q$.) In other words, we need to show that the composition 
\begin{align*}
P \xrightarrow \sigma \onetype + A \times A^* \xrightarrow \consterm A^*
\end{align*}
is good. By using the definition of a good  functions, we can show $\sigma$ is a composition
\begin{align*}
P \xrightarrow g  P_1 + P_2 \times P_3^* \xrightarrow { \sigma_1 + \sigma_2 \times \sigma_3^*} \onetype + A \times A^* 
\end{align*}
for some polyregular function $g$ and some  good functions 
\begin{align*}
P_1 \xrightarrow {\sigma_1} \onetype \qquad 
P_2 \xrightarrow {\sigma_2} A \qquad 
P_3 \xrightarrow {\sigma_3} A.
\end{align*}
We can ensure that the first good function is the identity on $\onetype$, and the other two good functions $\sigma_2$ and $\sigma_3$ are the same,  by using the co-pairing 
\begin{align*}
P_2 + P_3 \xrightarrow {\either {\sigma_2} {\sigma_3}} A,
\end{align*}
which is easily seen to be good. Summing up, if we write $\rho$ for the above co-pairing and $R$ for its domain, we need to show that the following composition is good:
\begin{align*}
P \xrightarrow g  \onetype + R \times R^* \xrightarrow { \idterm + \rho \times \rho^*} \onetype + A \times A^* \xrightarrow \consterm A^*.
\end{align*}
The atomic function $\consterm$ is natural in the sense that it commutes with $\rho$, and therefore the above composition is the same as
\begin{align*}
P \xrightarrow g  \onetype + R \times R^* \xrightarrow \consterm R^* \xrightarrow {\rho^*} A^*
\end{align*}
This is a composition of two polyregular functions on arrow-free types, namely $g$ and $\consterm$, followed by the list combinator applied to a good function. Therefore, it is good by the definition of good functions at a list type. This completes the proof of the induction basis for the atomic function $\consterm$.

The proof for the remaining atomic functions is similar. The first observation is that each atomic function is not a single function, but a family of functions 
\begin{align*}
F(A_1,\ldots,A_n) \xrightarrow {f_{A_1,\ldots,A_n}} G(A_1,\ldots,A_n)
\end{align*}
which is indexed by some type parameters $A_1,\ldots,A_n$ (for our system, there are at most three parameters), in which the inputs and outputs are expressions constructed from the type parameters using the arrow-free type constructors. Furthermore, each of the atomic functions will turn out to be natural in the following sense.

\begin{definition}[Natural transformation] \label{def:natural-transformation}
    Consider a family of functions
    \begin{align*}
F(A_1,\ldots,A_n) \xrightarrow {f_{A_1,\ldots,A_n}} G(A_1,\ldots,A_n) \qquad \text{for every types $A_1,\ldots,A_n$},
\end{align*}
where the input and output types are expressions constructed from the type parameters using the arrow-free type constructors. This family is called a \emph{natural transformation} if for every functions
\begin{align*}
A_1 \xrightarrow{ \rho_1} B_1 \quad \cdots \quad 
A_n \xrightarrow{ \rho_n} B_n,
\end{align*}
which are not required to be good or polyregular,  the following diagram commutes
\[
\begin{tikzcd}
[column sep=huge]
F(A_1,\ldots,A_n)
\arrow[r,"{f_{A_1,\ldots,A_n}}"] 
\arrow[d,"{F(\rho_1,\ldots,\rho_n)}"']
 & G(A_1,\ldots,A_n) 
 \arrow[d,"{G(\rho_1,\ldots,\rho_n)}"] 
\\
F(B_1,\ldots,B_n)
 \arrow[r,"{f_{B_1,\ldots,B_n}}"'] 
& G(B_1,\ldots,B_n),
\end{tikzcd}
\]
where $F$ and $G$ are lifted from types to functions in the expected way.
\end{definition}

\begin{claim}\label{claim:atomic-functions-are-natural-transformations}
    All atomic functions in the polyregular system are natural transformations.
\end{claim}
\begin{proof}
    Routine inspection.
\end{proof}
The second ingredient is the following claim, which is a generalisation of the argument we used for the list constructor about the shape of good functions at types constructed from arrow-free type constructors.

\begin{claim}\label{claim:functors-applied-to-good}
    Let $F(A_1,\ldots,A_n)$ be an expression that is built using the arrow-free type constructors $\onetype, +, \times$ and $*$, and let $A_1,\ldots,A_n$ be higher-order types. A function 
    \begin{align*}
    P \xrightarrow \rho F(A_1,\ldots,A_n)
    \end{align*}
    is good if and only if it can be described as  a composition
    \begin{align*}
    P \xrightarrow f F(P_1,\ldots,P_n) \xrightarrow {F(\rho_1,\ldots,\rho_n)} F(A_1,\ldots,A_n)
    \end{align*}
    for some polyregular function $f$ and good functions $P_i \xrightarrow {\rho_i} A_i$.
\end{claim}

Using the above claims, we can now prove that for each atomic function, the corresponding parametrised denotation is good. Consider an  atomic function 
\begin{align*}
F(A_1,\ldots,A_n) \xrightarrow {f_{A_1,\ldots,A_n}} G(A_1,\ldots,A_n),
\end{align*}
where the domain and co-domain are expressions built using the arrow-free type constructors. 
Similarly to the case of the list constructor, proving that the parametrised denotation $\semparam {f_{A_1,\ldots,A_n}} Q$ is good means showing that composing the non-parametrised denotation $\sem {f_{A_1,\ldots,A_n}}$ with a good function of type 
\begin{align*}
P \xrightarrow \rho F(A_1,\ldots,A_n)
\end{align*}
yields a good function. By the above two claims such a composition is described by the following commuting diagram
\[
\begin{tikzcd}
[column sep=huge]
P 
\ar[r,"f"]
\ar[dr,"{\rho}"', bend right=15]
& 
F(P_1,\ldots,P_n)
\arrow[r,"{f_{P_1,\ldots,P_n}}"] 
\arrow[d,"{F(\rho_1,\ldots,\rho_n)}"']
 & G(P_1,\ldots,P_n) 
 \arrow[d,"{G(\rho_1,\ldots,\rho_n)}"] 
\\
& F(A_1,\ldots,A_n)
 \arrow[r,"{f_{A_1,\ldots,A_n}}"'] 
& G(A_1,\ldots,A_n).
\end{tikzcd}
\]
The upper path in the above diagram consists of a composition of two polyregular functions on arrow-free types, followed by the output expression applied to some good functions. Therefore, it is good by \cref{claim:functors-applied-to-good}. This completes the proof of the Fundamental Lemma, and thus also the proof of \cref{thm:higher-order-terms}.
