`Transducers.rationalRel_equivalence_undecidable` (in `RequestProject/PartB/RationalStatements.lean`) now reads

```
theorem rationalRel_equivalence_undecidable (hPCP : ¬ ComputablePred PCP.Solvable) :
    ¬ ComputablePred (fun p : RelCode × RelCode => codeRel p.1 = codeRel p.2)
```

i.e. undecidability of equivalence of rational relations, from an explicit hypothesis that the Post correspondence problem is undecidable. It is proved by a computable many-one reduction from PCP (`RequestProject/PartB/PCPRed.lean`: the reduction sends a PCP instance to two codes whose relations are equal exactly when the instance has no solution, and the map is shown primitive recursive). **New: Lemma B.4.3 is now proved** (`Transducers.rationalFun_lengthPreserving_decidable`) — one can decide whether a coded rational relation is length preserving. Two new files:
* `RequestProject/PartB/PathComb.lean` — reusable combinatorics of paths in an automaton: splitting a path at a visited state, pigeonhole extraction of a nonempty loop of length at most the number of states, replacing a path by a simple one.
* `RequestProject/PartB/LenDec.lean` — the decision procedure: enumerate all transition sequences of length at most `3n` (`n` a bound on the number of states) and check that the accepting ones read and write strings of equal length. Correctness is a pumping argument, and the procedure is shown primitive recursive, hence `Computable`. The procedure is correct for *every* code, so it does not need the promise. I sanity-checked it by evaluation on small automata.

**A formalization defect found and fixed.** The promise used in the decidability statements of Sections B.3–B.4 was "the code describes a total function on all of `ℕ*`". I proved this is *never satisfiable* (`Transducers.not_codeTotalFunctional`): a code has finitely many transitions and so reads only finitely many letters. Left unchanged, it would have made those statements vacuously true. The promise `CodeFunctional` is now totality on the strings over the alphabet of the code, and the statement of Theorem B.4.2 was relativised in the same way; the original version is kept in the file as a comment with an explanation.

## What is still open

Four Part B statements remain `sorry`: B.3.3, B.3.4, B.3.7 and B.4.2. These are not gaps in the mathematics but in *effectivity*:
* B.3.3 and B.3.7 need a total computable procedure on codes of weighted automata over ℚ. The mathematical criterion (Schützenberger's bound) is proved in `RequestProject/PartB/WeightedZero.lean`; what is missing is an effective form of the bound and a computable evaluation of a coded weighted automaton. A concrete obstacle here is that Mathlib's `Primrec`/`Computable` API contains no arithmetic on `ℤ` or `ℚ` at all, so that API would have to be developed first.
* B.3.4 is derived from B.3.3 in the book, and B.4.2 requires deciding prefix preservation, which needs a synchronised product construction on codes.
