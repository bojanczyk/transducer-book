## Why, precisely

A code describes a function on **all** strings over its alphabet, so the map that is iterated is the induced map
on all of `A*`, and (`codeIteratesFinite_iff_uniform`) finiteness of the set of iterates asks for a single pair
`n, k` bounding the orbit of *every* string. Under any encoding of machine configurations as strings, every
string is a configuration, reachable or not, so the property to be reduced to is uniform mortality — the machine
becomes periodic from *every* configuration within a bound independent of the tape length — not halting from an
initial configuration. The book's sketch (simulate on a tape of length `m`, halt when space runs out) bounds only
the runs starting at an initial configuration, and no regular condition on the strings kept alive can restrict the
iteration to those runs. The direction is also forced: finiteness of the set of iterates is semi-decidable, so the
undecidable set must be semi-decidable (`Acceptance.ATM`, not its complement). Producing families that are
uniformly mortal exactly when a given machine halts is Hooper's immortality theorem, whose known proofs go through
aperiodic tilings and the domino problem; none of that machinery exists in the project or in Mathlib, and it is a
development of its own size. That, and not the absence of an undecidable set, is the obstacle.
