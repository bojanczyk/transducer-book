* `Transducers.Exercises.ForwardStepRational` — new file `RequestProject/Exercises/ForwardStep.lean`. The docstring that used to justify this hypothesis was **inaccurate**: `stepSST true A k` has three registers (`res`, `grp`, `cur`), so the project's append-only single-register lemma does not apply. What is true for `d = true` is that every register update concatenates the three registers in the fixed order `res, grp, cur` and only appends new letters, so the machine is *order preserving*; the only thing a letter's contribution does not know is whether it will survive. That is a bimachine: the prefix automaton is the transducer's own state space `BS`, and the suffix automaton carries the next letter together with the map `phi : BS → Reg → Bool` recording which registers still reach the output. Rationality then follows from Theorem `thm:bimachines`. I corrected the "append-only" claim in the file header and in `EXERCISES.md`.

* `Transducers.Exercises.ForwardPrenexNormalForm` — new file `RequestProject/Exercises/ForwardPrenex.lean`. Reading the existing proof of Lemma `lemma:prenex-normal-form` confirms the task's expectation almost entirely: `trFor` reproduces the direction of every loop it translates, and the extra loop it adds for a sequential composition (via `mergeLoops`) is first-to-last (`fwd_trFor`). The construction introduces **exactly one** last-to-first loop — the `(false, lv)` loop of `exec_nest_big`, whose only purpose is to bind `lv` to the *last* position. So the construction as written does not preserve forwardness, but the failure is repairable rather than essential: nothing in the merging construction uses that the second designated position is the last one, only that it comes *after* the first. I therefore generalised `Transducers.exec_merge` (`PartD/ForMerge.lean`), `Transducers.exec_merge_fresh` and `Transducers.trFor_spec` (`PartD/ForPrenex.lean`) **in place**, from `pos zv = 0 ∧ pos lv = w.length - 1` to `pos zv < pos lv ∧ pos lv < w.length`. The book's prenex form is the instance `0, w.length - 1` (unchanged, still proved), and the forward one is the instance `0, 1`, with the nest `(true, zv) :: (true, sv) :: (true, k') :: L` (`exec_nest_big_fwd`, `forwardPrenex`).
