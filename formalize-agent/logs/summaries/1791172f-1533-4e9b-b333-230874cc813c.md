**How the argument goes.** The easy direction reruns the pairing/co-pairing/map proofs of Part C for polyregular functions, which needed concatenation, case distinction over a regular language and the map lifting for polyregular functions (`PartD/PolySum.lean`, `PartD/PolyMapLift.lean`, `PartD/PolyRepr.lean`). The book's one-line proof that the new atom is polyregular — an outermost loop marks the comma separating prefix from suffix — is made explicit by `Transducers.perSplit` (`PartD/PolyPerSplit.lean`): applying a regular function to every copy of the input with a prefix underlined is polyregular, because the marked square of the input with a marker in front is, after a letter map, exactly the list of those copies. For the atom itself (`PartD/PolySplitsAtom.lean`) the string run over is the representation with its top-level commas marked, followed by a separator and a sentinel; a four-state automaton selects the cuts that fall between two entries, and a sequential rewriting emits the corresponding pair. The converse goes through the prime decomposition, and the step the book leaves to the reader is `Transducers.isPolyregularTermFun_markedSquare`: marked squaring is `split ; reverse ; tail ; map (map inl × map inr) ; map append ; concat`, which is the book's own worked example of the new atom, with the reverse and the tail correcting for the order of `splitsList` and for its extra pair.

Two constructions were built for this and are new in the project: `isPolyregular_mapLift_markedSquare` (the map lifting of marked squaring, as a computation over all the cuts of the whole input keeping the block in which the cut falls) and `sumLeftPoly_markedSquare` (the sum of marked squaring with the identity, obtained from the former by cutting the two summands into blocks in two different ways).
